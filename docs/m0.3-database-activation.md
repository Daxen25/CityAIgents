## Required correction before activation

**Revoke direct anonymous function grants, not only PUBLIC grants.** Supabase may grant
EXECUTE directly to `anon` via default privileges. Revoking PUBLIC does not remove those
grants. The current tests use vanilla PostgreSQL ACL defaults and did not model this.
A local reproduction with Supabase-style defaults left all three public RPC wrappers
executable by `anon`. Their private-schema restrictions still denied anonymous mutations
in that setup; this is a privilege defect, not a demonstrated anonymous write exploit.

In foundation, change exactly the three `from public;` clauses to `from public, anon;`:

1. `revoke all on schema private from public, anon;`
2. `revoke all on function private.workspace_role(uuid) from public, anon;`
3. The final REVOKE over all six create/transition functions: end it with
   `from public, anon;`.

Existing authenticated grants remain unchanged. Do not globally alter privileges for
unrelated platform functions. Existing migration files are unchanged during this review.
Because none is applied remotely, make these narrow edits to foundation before the CLI
route. Do not add a redundant schema-creation migration or rename version IDs.

migration discovery directory. That bundle is a review artifact, not a fourth migration.
